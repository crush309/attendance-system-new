# 按姓名保存考勤分组

2026-10-29：修复不同考勤表编号对应人员变化导致的分组串人问题。

## 行为

- 分配、查看成员、移除、导入匹配、分组导出均使用姓名。
- 去掉姓名首尾空白，保留姓名中间字符；同名视为同一人，空姓名不能分配。
- 本地 SQLite 与线上 PostgreSQL 使用独立的 employee_name_groups 表；相同姓名可属于多个组，重复分配不重复计数。
- 原 employee_groups 仅保存历史编号记录，禁止自动解释为姓名。组名保留，页面提示管理员按姓名重新分配一次。账号、权限和考勤规则保持不变。
- 成员姓名可在未导入文件时查看，修改分组后当前统计标签同步刷新。
- 旧版 emp_ids/emp_id 请求不再接受，更新后应刷新旧页面。

## 验证

- 新测试先复现旧版姓名请求被拒绝、编号请求被接受、历史编号被错误当作当前成员等问题。
- `python -m unittest discover -s tests -v`：12 项通过，包括正常及 Vercel 入口的换编号导入、按组导出、移除、空姓名拒绝，以及旧数据库保留和重新初始化后持久化。
- 用户提供的 A215 与 D303 两份九月原表分别 68、70 条记录，有 17 个相同编号对应不同姓名；以第一份姓名分组后，第二份正确匹配 58 个同名人员，零编号串人，分组导出名单一致。原始文件未修改或提交。
- 本地网页操作验证：分组测试甲从编号 001 变为 099 后仍属于原组，接替编号 001 的分组测试丙未继承分组。
- 独立代码复核未发现阻碍发布的问题；PostgreSQL SQL 已静态复核，线上部署后检查实际接口与页面。
